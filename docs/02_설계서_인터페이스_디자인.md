# 간편장부 웹앱 설계서 — 데이터·API·화면·출력양식

> 기반: `01_분석보고서.md`
> 대상 스택: Google Sheets(저장) + Google Apps Script(API) + GitHub(소스·정적 페이지)
> 원칙: 계약(타입·API)을 먼저 확정하고 구현은 이를 따른다. 저장은 거래 원장만, 보고서는 매번 계산한다.

## 0. 아키텍처 결정

### 0.1 배포 방식 — 두 안 중 A 권장

| | A. Apps Script가 화면까지 제공 (권장) | B. GitHub Pages 화면 + Apps Script API |
|---|---|---|
| 로그인 | Google 계정으로 자동, 웹앱 "액세스: 나만" | 직접 구현 필요(공유 토큰 등). "나만" 배포는 GitHub Pages에서 CORS로 호출 불가 |
| 개인정보 노출 위험 | 낮음 | 토큰 유출 시 사업자 정보·매출 전체 노출 |
| GitHub 역할 | 소스 저장소(clasp push), 사용 안내 페이지, 릴리스 | 화면 호스팅 + 소스 |
| 화면 코드 | 동일 (아래 계약을 그대로 사용) | 동일 |

세금·개인정보를 다루므로 **A안**을 기본으로 설계하고, 화면 코드가 호출하는 함수를 하나(`api(action, payload)`)로 고정해 **B안으로 전환할 때 전송 계층만 바꾸면** 되게 합니다.

```
[브라우저 UI]  ──api(action,payload)──▶  [전송 계층]
                                          A: google.script.run.api(...)
                                          B: fetch(EXEC_URL, POST text/plain JSON)
                                       ▶ [Code.gs  api() 디스패처]
                                          ├ 검증(경계에서만)
                                          ├ 서비스(transactions/partners/…)
                                          └ 보고서 계산(reports)
                                       ▶ [Google Sheets]
```

### 0.2 공통 응답 봉투

Apps Script 웹앱은 HTTP 상태코드를 지정할 수 없으므로 **모든 응답을 같은 봉투**로 돌려줍니다.

```js
/** @typedef {{ ok: true, data: any } | { ok: false, error: ApiError }} ApiResponse */
/** @typedef {{ code: ErrorCode, message: string, details?: object }} ApiError */
/** @typedef {'VALIDATION_ERROR'|'NOT_FOUND'|'CONFLICT'|'UNMAPPED_CATEGORY'|'UNAUTHORIZED'|'INTERNAL'} ErrorCode */
```

| code | 상황 | message 예시 |
|---|---|---|
| VALIDATION_ERROR | 입력 형식 오류. `details.fields`에 필드별 메시지 | 일자를 날짜형식('YYYY-MM-DD')으로 입력해 주세요. |
| NOT_FOUND | id 없음 | 해당 거래를 찾을 수 없습니다. |
| CONFLICT | 다른 곳에서 먼저 수정됨(`expectedUpdatedAt` 불일치), 중복 이름 | 다른 창에서 이미 수정되었습니다. 새로고침 후 다시 시도해 주세요. |
| UNMAPPED_CATEGORY | 명세서 항목이 지정되지 않은 거래구분이 보고서 기간에 존재 | (보고서는 계산하되 `warnings`로도 전달) |
| UNAUTHORIZED | B안에서 토큰 불일치 | 인증이 필요합니다. |
| INTERNAL | 그 외. 내부 메시지 노출 금지 | 일시적인 오류입니다. 잠시 후 다시 시도해 주세요. |

## 1. 저장 스키마 (Google Sheets, 시트 = 테이블)

모든 금액은 **원 단위 정수**. 날짜는 `YYYY-MM-DD` 문자열로 저장(시간대 문제 회피). 1행은 헤더(영문 키), 시트 이름도 영문.

### 1.1 `transactions` — 거래 원장

| 열 | 키 | 타입 | 필수 | 설명 |
|---|---|---|---|---|
| A | id | string | 서버 | 원본과 같은 `A{일련번호}A` 형식, `settings.nextSeq`로 발급 |
| B | date | `YYYY-MM-DD` | ✔ | |
| C | kind | `INCOME`/`EXPENSE`/`ASSET` | ✔ | 화면 표시: 수입/비용/고정자산매입 |
| D | category | string | ✔ | `categories.name` 중 하나(같은 kind) |
| E | description | string | | 내용, 최대 200자 |
| F | partner | string | | 거래처명(자유 입력 허용, 마스터 자동완성) |
| G | supplyAmount | int ≥ 0 | ✔ | 공급가액(원본 "금액") |
| H | vatAmount | int ≥ 0 | | 부가세, 기본 0 |

### 1.2 `categories` — 거래구분 + 명세서 매핑 (문제 #1·#4 해결)

| 키 | 타입 | 설명 |
|---|---|---|
| kind | INCOME/EXPENSE/ASSET | |
| name | string | 같은 kind 안에서 유일 |
| formLine | FormLine \| '' | 부표 반영 항목. **EXPENSE·INCOME은 필수**, ASSET은 비워둠(필요경비 미반영) |
| sortOrder | int | 표시 순서(원본 오름/내림 정렬 기능 대체) |
| isActive | bool | 삭제 대신 숨김(과거 거래 보존) |

```js
/** 부표 항목 코드 (번호는 서식 번호 그대로)
 * @typedef {'L11'|'L12'                                  // 수입: 매출액, 기타
 *  |'L15_GOODS'|'L19'|'L22'|'L23'                        // 상품매입, 재료매입, 제조노무비, 제조경비
 *  |'L25'|'L26'|'L27'|'L28'|'L29'|'L30'|'L31'|'L32'

```

초기 매핑(원본 표준 항목): 매출·수강료→L11, 기타(수입)→L12, 상품매입→L15_GOODS, 재료매입→L19, 제조노무비→L22, 제조경비→L23, 급료·월급여→L25, 제세공과금→L26, 임차료→L27, 지급이자→L28, 접대비→L29, 기부금→L30, 감가상각비→L31, 차량유지비→L32, 지급수수료→L33, 소모품비→L34, 복리후생비→L35, 운반비→L36, 광고선전비→L37, 여비교통비→L38, 기타(비용)→L39.
사용자 추가 항목(한솔교재비, 학원연합회, 책임보험, 학원운영비, 가맹지급수수료, 공인인증수수료, 한솔지사모임 회비)은 **마이그레이션 시 비워두고**, 첫 화면에서 매핑을 고르도록 안내합니다(세무 판단 영역).

## 2. 도메인 타입 (입력과 출력 분리)

```js
/** @typedef {'INCOME'|'EXPENSE'|'ASSET'} Kind */
/** @typedef {'SEPARATE'|'NONE'} VatMode */

/** 입력: 클라이언트가 보내는 것 */
/** @typedef {{
 *   requestId: string,          // 폼을 열 때 한 번 생성, 재시도에도 동일
 *   date: string, kind: Kind, category: string,
 *   description?: string, partner?: string,
 *   supplyAmount: number, vatAmount?: number,   // vatAmount 생략 시 vatMode로 서버 계산
 *   vatMode?: VatMode,                          // 생략 시 settings.vatDefault[kind]
 *   evidence?: string, memo?: string
 * }} CreateTransactionInput */

/** @typedef {{ id: string, expectedUpdatedAt: string } & Partial<Omit<CreateTransactionInput,'requestId'>>} UpdateTransactionInput */

/** 출력: 서버가 돌려주는 것 */
/** @typedef {{
 *   id: string, date: string, kind: Kind, category: string,
 *   description: string|null, partner: string|null,
 *   supplyAmount: number, vatAmount: number, totalAmount: number,
 *   evidence: string|null, memo: string|null, vatMode: VatMode,
 *   createdAt: string, updatedAt: string
 * }} Transaction */

/** @typedef {{ data: any[], pagination: { page: number, pageSize: number, totalItems: number, totalPages: number }, sums?: object }} Page */
```

### 부가세 규칙 (원본 4.2를 명시화)
- `vatMode=SEPARATE` 이고 `vatAmount` 생략 → `vatAmount = floor(supplyAmount × 0.1)` (원본의 절사 동작 유지)
- `vatMode=NONE` → `vatAmount = 0`
- 사용자가 `vatAmount`를 직접 보내면 그 값을 존중(영수증 금액과 맞추기 위해), 단 `totalAmount`는 항상 서버가 합산

## 3. API 계약

호출 형태: `api(action, payload) → ApiResponse`. 동사형 이름이 아니라 `자원.동작` 형식.

### 3.1 거래

| action | payload | data |
|---|---|---|
| `transactions.list` | `{ from?, to?, kind?, category?, partner?, evidence?, q?, qField?: 'category'\|'description'\|'partner'\|'evidence'\|'memo', exact?: bool, page=1, pageSize=50 (최대 500), sortBy='date', sortOrder='desc' }` | `Page<Transaction>` + `sums: {supply, vat, total}` (필터 전체 기준) |
| `transactions.get` | `{ id }` | `Transaction` |
| `transactions.create` | `CreateTransactionInput` | `Transaction` |
| `transactions.update` | `UpdateTransactionInput` (부분 수정) | `Transaction` |
| `transactions.delete` | `{ id }` | `{ deleted: bool }` — 이미 없어도 성공(멱등) |
| `transactions.bulkDelete` | `{ ids: string[] }` (최대 500) | `{ deletedCount }` |

- `from`·`to`는 둘 다 주거나 둘 다 생략(원본 규칙), 생략 시 올해.
- `exact=false`면 부분일치(원본 기본), `true`면 완전일치.

### 3.2 거래처 · 거래구분 · 설정

| action | payload | data |
|---|---|---|
| `partners.list` | `{ q?, page, pageSize }` | `Page<Partner>` |
| `partners.create` / `update` / `delete` | `{...}` / `{id, ...}` / `{id}` | `Partner` / `Partner` / `{deleted}` |
| `categories.list` | `{ kind? }` | `Category[]` (페이지 불필요, 최대 수십 개) |
| `categories.create` | `{ kind, name, formLine }` | `Category` — INCOME/EXPENSE는 formLine 없으면 VALIDATION_ERROR |
| `categories.update` | `{ kind, name, formLine?, sortOrder?, isActive?, newName? }` | `Category` — 이름 변경 시 과거 거래도 일괄 변경 |
| `settings.get` / `settings.update` | `{}` / 부분 객체 | `Settings` |
| `adjustments.get` / `adjustments.put` | `{ year }` / `{ year, ...값 }` | `Adjustments` |

원본의 "거래구분 수기 입력 시 자동 등록"은 **유지하지 않습니다** — 자동 등록된 항목이 매핑 없이 쌓인 것이 문제 #1의 원인. 화면에서 "새 거래구분 추가" 버튼으로 매핑과 함께 등록합니다.

### 3.3 보고서 (항상 즉석 계산, 저장하지 않음)

| action | payload | data |
|---|---|---|
| `reports.dashboard` | `{ year, date }` | `{ monthly: [{month, INCOME, EXPENSE, ASSET}×12], yearTotal, prevYearTotal, diff, diffRate, allTimeTotal, quarterly: [...4], day: { INCOME:{supply,vat,total,rateVsPrevDay}, EXPENSE:{…}, ASSET:{…} } }` |
| `reports.monthly` | `{ year, kind? }` | `{ rows: [{kind, category, months:[12], total}], quarterSubtotals, grandTotal }` |
| `reports.byKind` | `{ kind, category?, evidence?, from, to, page, pageSize }` | `Page<Transaction>` + 합계 |
| `reports.byPartner` | `{ partner, from, to }` | `{ rows: Transaction[], periodSum: {count, INCOME, EXPENSE, ASSET}, cumulativeSum: {…} }` |
| `reports.expenseStatement` | `{ year }` | `{ header: Header, lines: Record<'L11'..'L41', number>, warnings: Warning[] }` |
| `reports.incomeStatement` | `{ year }` | `{ header: Header, lines: Record<'L11'..'L22', number>, submittedOn: string, warnings }` |

```js
/** @typedef {{ code: 'UNMAPPED_CATEGORY', category: string, kind: Kind, amount: number }} Warning */
/** @typedef {{ year:number, periodFrom:string, periodTo:string, ownerName, birthDate, address, phone, bizAddress, industry, industryCode, bizNo }} Header */
```

`incomeStatement`는 내부에서 `expenseStatement`를 호출해 (11)=(13), (15)=(41)을 가져옵니다 → 문제 #2가 구조적으로 발생할 수 없음.

### 3.4 내보내기

| action | payload | data |
|---|---|---|
| `export.csv` | `transactions.list`와 같은 필터 | `{ filename, csv }` (UTF-8 BOM, 엑셀에서 한글 안 깨짐) |

### 3.5 서버 측 검증 규칙 (경계에서 한 번만)

| 필드 | 규칙 | 오류 메시지 |
|---|---|---|
| date | `YYYY-MM-DD`, 실제 존재하는 날짜 | 일자를 날짜형식('YYYY-MM-DD')으로 입력해 주세요. |
| kind | 3개 enum | 거래종류를 선택해 주세요. |
| category | 같은 kind의 활성 거래구분 | 거래구분을 선택해 주세요. |
| supplyAmount | 정수, 0 이상, 1조 미만 | 금액을 숫자형식으로 입력해 주세요. |
| vatAmount | 정수, 0 이상 | 부가세를 숫자형식으로 입력해 주세요. |
| evidence | enum 또는 빈 값 | 증빙을 목록에서 선택해 주세요. |
| 텍스트 | 앞뒤 공백 제거, 길이 제한, `=+-@`로 시작하면 앞에 `'` 붙여 저장(시트 수식 주입 방지) | |

### 3.6 중복 제출 방지와 동시 수정

- **중복 제출**: `create`는 `requestId` 필수. 클라이언트는 입력 폼을 열거나 저장 성공 후 초기화할 때 `crypto.randomUUID()`로 **한 번** 만들고, 네트워크 재시도에는 같은 값을 씁니다. 서버는 `LockService.getScriptLock()` 안에서 `requestId` 존재 확인 → 없으면 추가 (시트에는 유일 제약이 없으므로 잠금이 원자성을 보장). 이미 있으면 그 거래를 그대로 반환. 같은 `requestId`인데 내용이 다르면 `CONFLICT`.
- **동시 수정**: `update`는 `expectedUpdatedAt`이 시트 값과 다르면 `CONFLICT`.
- **삭제**는 멱등이라 재시도 안전.

### 4.4 거래처 · 거래별 · 거래처별 · 월별
- **거래처**: 표 + 검색 + 추가/수정/삭제 폼(상호명·대표자·사업자번호·담당자·전화·비고). 사업자번호 입력 시 하이픈 자동.
- **거래별현황**: 종류(필수)·거래구분·증빙·기간 → 목록 + 합계.
- **거래처별현황**: 거래처(자동완성)·기간 → 목록 + "합계 n건 / 누계 n건".
- **월별현황**: 종류 탭(전체/수입/비용/고정자산) → 거래구분 × 1~12월, 3·6·9·12월 뒤 분기 소계 열, 합계 행(배경 `--total-bg`).

### 4.5 설정
1. 기본정보 / 사업장 정보 폼 (주민등록번호 칸 없음)
2. 거래구분 관리: kind별 목록, 드래그 정렬, **명세서 항목 드롭다운**, 숨김 토글. 미매핑 항목은 빨간 배지 + 대시보드 상단 경고 배너 "명세서 항목이 지정되지 않은 거래구분 2개(4,613,300원)가 필요경비에서 빠져 있습니다."
3. VAT 기본값: 수입/비용/고정자산 각각 별도/없음

## 10. 확인 체크리스트
- [ ] 모든 action에 입력·출력 타입이 있다
- [ ] 오류는 한 가지 봉투(`{ok:false,error}`)로만 나온다
- [ ] 검증은 `api()` 진입부에서만 한다
- [ ] 목록 action은 페이지를 지원한다
- [ ] `create`는 requestId + 스크립트 잠금으로 중복을 막는다
- [ ] `update`는 expectedUpdatedAt으로 충돌을 감지한다
- [ ] 보고서는 저장하지 않고 매번 계산한다, 계산서는 부표 결과를 그대로 쓴다
- [ ] 명세서 항목이 없는 거래구분은 경고로 드러난다
